# Inheritance

## المفهوم
الوراثة (Inheritance) بتديّك القدرة على أخذ الـ **behavior** (methods)
والـ **state** (properties) الموجودة في كلاس أب (super class)،
وتوريثها لكلاس ابن (subclass) بدون الحاجة لإعادة كتابتها.

الهدف الأساسي: **تقليل تكرار الكود (code duplication)**. لو عندك
سلوك مشترك بين أكتر من نوع، تكتبه مرة واحدة بس في الكلاس الأب،
وكل الأنواع اللي محتاجاه بترثه جاهز.

## مثال من الحياة الواقعية
كل عربية (Car) وموتوسيكل (Motorcycle) بيقدروا يسرعوا (`accelerate`)
ويفرملوا (`brake`) — السلوك ده مشترك بينهم. لكن العربية عندها كلاكس
(`honk`) والموتوسيكل عنده wheelie — سلوك خاص بكل نوع لوحده.

بدل ما تكتب `accelerate`/`brake` في كل كلاس منفصل، تكتبهم مرة واحدة
في `Vehicle`، و`Car` و`Motorcycle` بيورثوهم جاهزين.

## متى تستخدمها؟
لما يكون عندك علاقة منطقية حقيقية بين نوعين — "Car IS-A Vehicle"،
"Motorcycle IS-A Vehicle" — مش مجرد تشابه سطحي في الشكل. لو العلاقة
مش IS-A حقيقية، الوراثة ممكن تسبب مشاكل تصميم (زي إجبار subclass
على وراثة methods مش منطقية بالنسبة له).

## الفرق بين Inheritance و Interface
| | Inheritance | Interface |
|---|---|---|
| إعادة كتابة الـ methods | مش لازم — بتورث التنفيذ الجاهز | **لازم** تنفذ كل method معلنة فيها |
| عدد العلاقات المسموحة | عادة كلاس واحد بس (`extends`) | ممكن تعمل `implements` لأكتر من واحدة |
| بتورث state (properties)؟ | أيوه | لأ، الـ interface بتعرّف الشكل بس من غير state |

الفرق الجوهري: الوراثة بتديك **تنفيذ جاهز** تقدر تستخدمه أو تعدّل
عليه (override)، أما الـ interface بتفرض عليك **عقد (contract)**
لازم تكتب تنفيذه بنفسك بالكامل.
