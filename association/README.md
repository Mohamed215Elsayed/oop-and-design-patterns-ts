# Association (UML Relationship)

## المفهوم
Association هي علاقة استخدام بسيطة بين object وobject تاني — كلاس
بيستخدم كلاس تاني (بينده على method بتاعته أو بياخده كـ parameter)،
لكن من غير أي علاقة ملكية أو اعتماد وجودي بينهم.

## الفرق الجوهري
لو الـ object الأول (`Website`) اتمسح، الـ object التاني
(`WebsiteContent`) بيفضل شغال عادي تمامًا — لأنه مش "مملوك" ليه،
هو بس بيتعامل معاه مؤقتًا.

في المثال: مسحنا الـ `website` (`website = null`)، ومع ذلك
`listContent` و `paragraphContent` فضلوا شغالين عاديين، لأنهم
مستقلين تمامًا عن وجود الـ `Website`.

## متى تستخدمها؟
لما يكون عندك كلاس محتاج "يستخدم" كلاس تاني بشكل مؤقت (زي parameter
جوه method)، من غير ما يبقى فيه علاقة تبعية دائمة أو ملكية.

## الفرق بينها وبين Composition/Aggregation
- **Association** → استخدام مؤقت، مفيش ملكية خالص.
- **Aggregation** → علاقة "has-a" لكن الجزء ممكن يعيش لوحده حتى لو
  الكل اتمسح.
- **Composition** → علاقة "owns-a" قوية، لو الكل اتمسح الجزء بيتمسح
  معاه (life-cycle مرتبط بالكامل).
